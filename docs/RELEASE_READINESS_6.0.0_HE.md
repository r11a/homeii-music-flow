# מוכנות להפצת 6.0.0

עדכון התקנה: QA102 ו־Engine 0.7.21 הותקנו ב־2026-09-08, לאחר גיבוי ואימות כל ה־checksums. בדיקת HA עברה, בוצע restart והדשבורד החדש עלה עם Computer והמידע שלו. פרטי הגיבוי והמשאב ב־qa-matrix.md. אזכורי “טרם הותקן” להלן הם תיעוד היסטורי; שערי הקבלה המלאים עדיין פתוחים.

## עדכון המועמד המקומי — 2026-09-08, אחרי שילוב גרמנית

עדכון זה מחליף את נתוני הבנייה והבדיקות הישנים בהמשך המסמך; שערי הקבלה החיה נשארים פתוחים.

- גרמנית מ־PR #89 שולבה עם קרדיט ל־rtreichl, התאמת כל המפתחות והמשתנים למילון האנגלי, בחירה בהגדרות וזיהוי de-DE/de-AT.
- Engine המקומי הוא 0.7.21: pagination של הספרייה עם offset ומטמון נפרד לכל דף; היכולת נחשפת באמצעות library_pagination. עברו 52 בדיקות Engine ו־validator.
- תוקנו סדר אלבום עם metadata חלקי (#85), כשלי חיפוש ותגובות ישנות (#83), טעינת ספריות גדולות (#87) ונוספה הגדרת search_result_order (#86).
- תוקן Stop גם במסך הנגנים (#75). בדיקת runtime הופעלה מחדש מול חוזה Engine.
- lint עבר; 390 בדיקות עברו, 34 דילוגים ב־49 קבצים. נבדקה ספרייה של 691 פלייליסטים, כולל כשל בדף מאוחר ושינוי snapshot.
- npm ci מבודד עבר עם NODE_USE_SYSTEM_CA=1, ללא ביטול אימות TLS. הבנייה הנקייה והבנייה הראשית זהות: SHA256 F8DDC902F74AC6A06FA5D7CE6CBE06935EADD1339612601874A85C058B8333CB.
- טרם הותקן המועמד: QA101 עדיין פעיל בבית. לא בוצעו merge, push, סגירת Issues או פרסום. אימות קבוצות, התקנה, חומרה פיזית ויתר שערי הקבלה עדיין נדרשים.

## תיעוד הסבב הקודם ושערי הקבלה

עודכן: 2026-09-08. זהו מעקב הכנה, לא אישור להפצה. הכרטיס הפעיל בבית עדיין QA101; השינויים המפורטים להלן נבנו מקומית וטרם הותקנו. לא בוצעו commit, push או פרסום גרסה בסבב זה.

## שינויים שנבנו בסבב הנוכחי

- נגנים שאינם זמינים מוסתרים מבחירה, העברת תור וקבוצות, וחוזרים לפי עדכוני המצב. המודל שומר את חברותם בקבוצה; ההסתרה אינה פקודת ניתוק.
- מניפה פתוחה ומסך כל הפעולות מתעדכנים עם הזמינות. הגלגל שומר את הפעולה המרכזית ככל האפשר ודוחה שינוי בזמן גרירה עד לשחרור האצבע. פעולה נבדקת מחדש לפני ביצוע.
- מניפת הנגן משתמשת בבדיקת הזמינות המשותפת, כולל available=false בנוסף למצב unavailable/unknown.
- אימות קבוצות דורש קריאת Engine חדשה אחרי הפקודה. כשל קריאה או תמונת מצב ישנה אינם נחשבים אישור להצלחת הקיבוץ. המידע האחרון נשמר לתצוגה בלבד.
- 21 מתודות קבוצות הועברו למודול speaker-groups תוך שמירת השמות והממשק בכרטיס. זהו צעד תחזוקה ממוקד; קובצי הליבה הגדולים עדיין דורשים עבודה נוספת.
- תוקן חישוב השהיית שומר המסך: היעדר override משתמש בזמן המוגדר, ולא ב־500 מילישניות.
- נוסף package-lock; תהליך CI הוכן ל־lint, tests, build ואימות קובצי ההפצה. פרסום תלוי בבדיקות ובהתאמת tag לגרסת החבילה. תהליך הבנייה מאמת התאמה בין גרסאות המקור, package והבנייה.
- גרסת pyproject של Engine יושרה ל־0.7.20 ונוסף אימות התאמתה ל־manifest. לא שונה runtime של Engine בסבב זה.

## ממצא חי: קבוצות Computer / Kitchen

הקבוצה שנוצרה מהכרטיס הופיעה תחילה עם שני חברים אך לא נשמרה בבדיקה המאוחרת. בבדיקת השוואה נוצרה אותה קבוצה ישירות בממשק MA; גם היא חזרה לאחר זמן לנגנים נפרדים. המצב האחרון שנבדק: Computer לבדו, Kitchen לא מסומן כחבר. לא הופעל ניגון ולא שונו עוצמות; נגנים אחרים לא שונו.

ההשוואה מצביעה על צורך בבירור גם בצד MA/ספק הנגנים, אך אינה מוכיחה את מקור התקלה. תיקון אישור המצב בכרטיס אינו מוצג כתיקון להתפרקות המאוחרת. יש לאסוף לוגים מתוזמנים סביב יצירת הקבוצה והשינוי המאוחר ולבדוק את פרוטוקול הקיבוץ לפני הכרזה על תמיכה יציבה.

## ראיות והגבלות

- baseline Engine: 51 בדיקות unittest עברו; validator עבר, וגם לאחר הוספת אימות התאמת גרסאות.
- פרטי בדיקות הכרטיס והבנייה האחרונה נרשמים ב־qa-matrix.md.
- ניסיון npm ci מבודד ב־.release/clean-install-20260908 נכשל: ניסיון offline חסר חבילה במטמון, והניסיון מול המאגר הסתיים בשגיאת npm פנימית. אין בכך הוכחת כשל במוצר, אך אין אישור להתקנה נקייה.
- GitHub Actions טרם רץ עם תצורת ה־CI החדשה. בנייה מקומית אינה תחליף לתוצאה ב־CI.
- שומר מסך/קריסת לשונית ועיכובי כלי דפדפן הפריעו לבדיקת הדשבורד. אין לייחס קריסות אלו לכרטיס ללא שחזור מבודד.
- בדיקות שמע וחומרה פיזית, soak ממושך והפצה ציבורית לא בוצעו בסבב זה.

## סדר ההתקדמות

1. להשלים בירור הקבוצות ואימות מצב טרי, ואז להתקין מועמד בדיקה חדש עם checksum ונתיב rollback.
2. לעבור את מטריצת התפעול והמסכים על אותו מועמד ולהשלים תרחישי GitHub הרלוונטיים להפצה.
3. לאמת התקנה נקייה, שדרוג ו־rollback ולסגור פערי תיעוד ובדיקות.
4. להכין tag ופרסום רק כששערי הקבלה מאומתים. אין כיום אישור שהמוצר מוכן להפצה יציבה.
